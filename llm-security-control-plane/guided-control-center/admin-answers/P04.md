# P04 UI 전용 독립 풀이 감사

## 판정

**가능하다.** UI 조건만으로 `invoke_guarded`의 채점 가능한 완성 답을 명확히 도출할 수 있다.

UI가 다음 사항을 모두 지정한다.

- `body`의 정확한 필드 집합과 각 필드의 허용값
- 모든 잘못된 입력을 서비스 호출 전에 `ValueError`로 거부할 것
- 허용한 `text`의 공백을 보존할 것
- 정책 식별자는 `body`가 아닌 서버 제공 `guardrail`에서 가져올 것
- operation별로 호출할 단 하나의 서비스 메서드
- ApplyGuardrail의 source, content, outputScope
- Converse의 모델, system, user 메시지, inferenceConfig, guardrailConfig
- 문자열을 직접 치환하지 않을 것
- 서비스 응답을 그대로 반환하고 서비스 오류를 그대로 전파할 것

`services` 메서드가 이름이 같은 AWS Bedrock Runtime 작업의 요청 구조를 받는 제공 객체라는 문제의 계약에 따라, `content`, `system`, `messages`의 표준 구조도 결정된다.

## 완성 답 전체

```python
async def invoke_guarded(body, guardrail, services):
    if not isinstance(body, dict):
        raise ValueError("Invalid body type")

    if set(body.keys()) != {"operation", "text"}:
        raise ValueError("Invalid fields")

    operation = body["operation"]
    text = body["text"]

    if not isinstance(operation, str):
        raise ValueError("Invalid operation type")
    if operation not in {"apply_guardrail", "converse"}:
        raise ValueError("Invalid operation")

    if not isinstance(text, str):
        raise ValueError("Invalid text type")
    if not 1 <= len(text) <= 1000:
        raise ValueError("Invalid text length")
    if not text.strip():
        raise ValueError("Blank text")

    if operation == "apply_guardrail":
        return await services.apply_guardrail(
            guardrailIdentifier=guardrail["guardrailIdentifier"],
            guardrailVersion=guardrail["guardrailVersion"],
            source="OUTPUT",
            content=[
                {
                    "text": {
                        "text": text,
                    }
                }
            ],
            outputScope="FULL",
        )

    return await services.converse(
        modelId="us.amazon.nova-lite-v1:0",
        system=[
            {
                "text": "사용자 문장을 그대로 한 번만 출력하세요. 다른 설명을 덧붙이지 마세요."
            }
        ],
        messages=[
            {
                "role": "user",
                "content": [
                    {
                        "text": text,
                    }
                ],
            }
        ],
        inferenceConfig={
            "maxTokens": 128,
            "temperature": 0,
        },
        guardrailConfig={
            "guardrailIdentifier": guardrail["guardrailIdentifier"],
            "guardrailVersion": guardrail["guardrailVersion"],
            "trace": "enabled",
        },
    )
```

## 채점 조건과의 대응

- `body`가 사전인지와 key 집합이 정확한지 먼저 검사하므로 누락 및 추가 필드는 서비스 호출 전에 거부된다.
- `operation`의 자료형을 별도로 검사하므로 list나 dict처럼 hash 불가능한 잘못된 값도 `TypeError`가 아니라 요구된 `ValueError`가 된다.
- `text.strip()`은 공백뿐인지 판정할 때만 사용하고 실제 요청에는 원래 `text`를 전달하므로 허용 문자열의 앞뒤 공백이 보존된다.
- `apply_guardrail` 분기는 `apply_guardrail`만 한 번 호출하고 즉시 그 응답을 반환한다.
- `converse` 분기는 `converse`만 한 번 호출하며 같은 Guardrail ID와 version을 `guardrailConfig`에 넣는다.
- 이메일을 직접 바꾸는 코드가 없다.
- 서비스 호출을 `try`/`except`로 감싸지 않아 호출 오류가 그대로 전달된다.
- 두 분기 모두 서비스 응답 객체를 복사하거나 수정하지 않고 그대로 반환한다.

## 누락 또는 모호성

채점 가능한 동작을 막는 누락 조건은 없다. 다음은 결과를 바꾸지 않는 구현 자유도다.

- `ValueError`의 메시지 문구는 지정되지 않았다.
- 검증 조건을 여러 `if`로 나눌지 하나로 합칠지는 자유다.
- 로컬 변수 이름은 자유다.

단, `services`가 AWS Bedrock Runtime과 다른 독자적인 인자 구조를 쓴다면 그 구조가 UI에 없으므로 답을 확정할 수 없다. 문제에서 AWS Guardrail, Converse, 각 AWS 필드명을 그대로 사용하고 있으므로 표준 Bedrock 요청 구조를 사용한다는 해석이 가장 직접적이며, 위 답은 그 계약에 따른다.
