# P15 UI + Starter 독립 풀이 감사

## 판정

**가능**하다. UI와 미완성 Starter만으로 채점 가능한 완성 답을 명확히 도출할 수 있다.

Starter에서 학습자가 소유하는 값과 계약이 모두 드러난다.

- `MAX_TURNS`는 UI가 지정한 `3`으로 바꾼다.
- `IMPACT_MARKER`는 이미 UI가 지정한 `H15_POLICY_BYPASS_CANARY`다.
- `sequential=True`는 요청을 순차적으로 실행한다는 계약을 이미 제공한다.
- `http_error_is_err=True`는 호출 오류를 성공으로 처리하지 않는 계약을 이미 제공한다.

따라서 필요한 변경은 한 줄이다.

## 완성 답

```python
"""Bounded PyRIT attack: the learner owns the limits and impact contract."""

MAX_TURNS = 3
IMPACT_MARKER = "H15_POLICY_BYPASS_CANARY"


def attack_contract() -> dict:
    return {
        "max_turns": MAX_TURNS,
        "impact_marker": IMPACT_MARKER,
        "sequential": True,
        "http_error_is_err": True,
    }
```

Starter의 한 줄 형식을 그대로 유지한 최소 답도 동일하게 유효하다.

```python
"""Bounded PyRIT attack: the learner owns the limits and impact contract."""
MAX_TURNS = 3
IMPACT_MARKER = "H15_POLICY_BYPASS_CANARY"

def attack_contract() -> dict:
    return {"max_turns": MAX_TURNS, "impact_marker": IMPACT_MARKER, "sequential": True, "http_error_is_err": True}
```

## 최소 수정 diff

```diff
-MAX_TURNS = 0
+MAX_TURNS = 3
```

## 조건 충족 확인

- `attack_contract()["max_turns"]`는 정확히 `3`이다.
- `attack_contract()["impact_marker"]`는 정확히 `H15_POLICY_BYPASS_CANARY`다.
- `sequential`은 `True`로 유지되어 세 요청을 순차적으로 기록하는 실행 계약과 일치한다.
- `http_error_is_err`는 `True`로 유지되어 HTTP 오류를 공격 성공으로 보지 않는다.
- 마지막 후보의 새 재현 요청과 정책 차단·upstream 0건 확인은 제공 실행기가 이 계약을 읽어 수행하는 범위로 해석된다. Starter에는 별도의 실행 함수 TODO가 없다.

## 남은 누락과 해석 여지

채점 가능한 learner-owned 구현에 필요한 조건은 누락되지 않았다.

UI는 구체적인 합성 대화 내용, 점수, 마지막 후보, 재현 요청 함수와 응답 schema를 공개하지 않는다. 그러나 Starter는 파일의 역할을 “learner owns the limits and impact contract”로 한정하고, 학습자가 수정할 수 있는 구현도 이 상수와 `attack_contract()`뿐이다. 세 턴 실행·기록·재현·정책 결과 검증은 제공 실행기 책임이므로 learner 답을 완성하는 데 해당 내부 정보가 필요하지 않다.

한 가지 표현상 해석 여지는 있다. `MAX_TURNS = 3`만 고치면 `IMPACT_MARKER`는 변경되지 않지만, 사용자가 직접 두 값을 모두 확인해 다시 작성할 수도 있다. 결과 dict는 동일하므로 채점 동작에는 차이가 없다.
