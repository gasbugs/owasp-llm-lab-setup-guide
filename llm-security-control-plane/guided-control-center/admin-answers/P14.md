# P14 UI+Starter 재감사

## 판정

**요구사항을 만족하는 완성 답을 작성할 수 있다.**

Starter가 파일의 전체 구조와 수정 위치를 보여 주며, UI가 필요한 세 `run` key와 허용값을 직접 제시한다. `soft_probe_prompt_cap`은 하나의 고정값이 아니라 1~4 범위이므로 정답은 비유일하지만, 범위 안의 값을 하나 선택하면 완성 YAML을 만들 수 있다.

## 완성된 `garak-config.yaml`

실행량을 가장 작게 유지하도록 cap `1`을 선택한 답은 다음과 같다.

```yaml
# CUSTOM FILE
# Format reference: https://reference.garak.ai/en/latest/configurable.html
# Upstream format license: Apache-2.0
run:
  soft_probe_prompt_cap: 1
  generations: 1
system:
  parallel_attempts: 1
```

이 답은 다음 조건을 모두 만족한다.

- probe 입력 후보 상한은 허용 범위 1~4 안의 `1`이다.
- 입력당 생성 횟수는 `1`이다.
- 동시 실행 수는 `1`이다.
- Starter에 없는 target, probe 또는 detector 설정을 새로 추가하지 않으므로 제공된 격리 대상과 사례를 외부 대상으로 확장하지 않는다.
- Garak 자체의 native report 동작을 끄거나 다른 report 형식으로 바꾸지 않는다.

## 다른 유효한 완성 답

UI가 `soft_probe_prompt_cap`을 1~4개라고 명시하므로 다음 세 값도 유효하다.

```yaml
run:
  soft_probe_prompt_cap: 2
  generations: 1
  parallel_attempts: 1
```

```yaml
run:
  soft_probe_prompt_cap: 3
  generations: 1
  parallel_attempts: 1
```

```yaml
run:
  soft_probe_prompt_cap: 4
  generations: 1
  parallel_attempts: 1
```

따라서 `1`은 유일한 값이 아니라 가장 작은 유효값을 선택한 것이다. 채점기가 UI와 일치한다면 1, 2, 3, 4를 모두 허용해야 한다.

## 남은 누락과 비유일성

완성 YAML을 작성하는 데 필요한 설정 계약은 제공됐다. 남는 사항은 다음과 같다.

- cap을 1~4 중 어느 값으로 고를지 정하는 추가 기준은 없다.
- 제공된 격리 대상과 probe 사례가 config 밖의 실행 명령 또는 컨테이너 entrypoint에서 어떻게 주입되는지는 공개되지 않았다. 다만 Starter에 관련 TODO나 key가 없으므로 학습자가 이 파일에서 작성할 항목으로 볼 근거가 없다.
- native JSONL report의 경로와 파일명은 공개되지 않았다. UI는 report 설정을 추가하라고 하지 않고 실제 제품 report를 확인한다고만 하므로 Garak의 제공 실행 경로가 이를 담당한다고 해석하는 것이 자연스럽다.
- 실제 Garak 0.15.1 실행과 report 결과는 이 텍스트만으로 검증할 수 없다. 이는 답 구성의 누락이라기보다 실행 검증이 별도로 필요하다는 한계다.

결론적으로 정답 값 하나만 존재하지는 않지만, UI+Starter만으로 채점 조건을 만족하는 전체 파일을 작성할 수 있다.
