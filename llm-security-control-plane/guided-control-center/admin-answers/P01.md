# P01 UI-only 최종 재감사

## 판정

**가능**하다. 문제 UI만으로 채점 가능한 `handle_request(body, client)`의 완성 답을 명확히 도출할 수 있다. UI는 함수 인터페이스, 입력 스키마와 경계값, 오류 방식, 모델 호출 인자, 예산 처리 순서, 반환값을 모두 제공한다.

## 완성 답

```python
def handle_request(body, client):
    if not isinstance(body, dict):
        raise ValueError("body must be a JSON object")

    if set(body) != {"message", "max_output_tokens"}:
        raise ValueError("exactly message and max_output_tokens are required")

    message = body["message"]
    requested_max_tokens = body["max_output_tokens"]

    if not isinstance(message, str):
        raise ValueError("message must be a string")
    if not 1 <= len(message) <= 4000 or not message.strip():
        raise ValueError("message must be 1 to 4000 non-blank characters")

    # bool은 Python에서 int의 하위 타입이므로 정확한 타입을 검사한다.
    if type(requested_max_tokens) is not int:
        raise ValueError("max_output_tokens must be an integer")
    if not 1 <= requested_max_tokens <= 512:
        raise ValueError("max_output_tokens must be between 1 and 512")

    actual_max_tokens = min(requested_max_tokens, 128)
    reservation_id = client.reserve_budget(actual_max_tokens)

    try:
        response = client.converse(
            modelId="us.amazon.nova-lite-v1:0",
            messages=[
                {
                    "role": "user",
                    "content": [{"text": message}],
                }
            ],
            inferenceConfig={
                "maxTokens": actual_max_tokens,
                "temperature": 0.0,
            },
        )
    except Exception:
        client.cancel_budget(reservation_id)
        raise

    client.settle_budget(
        reservation_id,
        response["usage"]["outputTokens"],
    )
    return response
```

## 누락 조건과 해석 여지

채점 가능한 핵심 계약에는 누락이 없다. 다음 세부 사항은 UI가 정하지 않았지만, 명시된 동작을 구현하거나 채점하는 데 필수적이지 않다.

- `ValueError`의 메시지 문구
- 여러 입력 오류가 동시에 존재할 때 검사할 순서
- `settle_budget()` 자체가 실패할 때 예약을 취소할지 여부. UI의 “호출 실패 시”는 문맥상 `client.converse()` 실패를 가리킨다.
- 문자 수의 정의. 별도 기준이 없으므로 Python 문자열의 `len()`을 적용하는 해석이 자연스럽다.

`reserve_budget()`가 예산 부족으로 실패하면 예약 ID가 생성되지 않으므로 취소나 모델 호출 없이 그 오류를 그대로 전달한다. 위 코드가 이 조건도 만족한다.
