# P17 최종 UI + Starter 독립 감사

## 판정

**완성 답을 정확히 도출할 수 있다.**

UI와 Starter가 다음 계약을 모두 제공한다.

- `observe_request`의 정확한 signature
- `run_business(stage)`의 호출 횟수와 반환 schema
- root 및 child Span 이름·attribute
- stage context manager의 동작과 sequence 규칙
- Trace ID 변환 방법
- root에 사후 기록할 decision, stop stage, stage count
- JSON Log의 정확한 필드
- Counter label과 증가 횟수
- 업무 반환값을 바꾸지 않고 돌려줘야 한다는 조건

## 완성 답 전체

```python
"""P17 learner artifact: instrument the provided business operation."""

import json
from contextlib import contextmanager


def observe_request(request_id, run_business, tracer, logger, counter):
    """Return the unchanged business result after producing its real signals.

    Run business once inside a root span. Supply a stage(name) context manager
    that creates ordered child spans. Record one structured decision log and
    increment one decision counter. Do not put request IDs in metric labels.
    """
    sequence = 0

    with tracer.start_as_current_span(
        "security.request",
        attributes={"request_id": request_id},
    ) as root_span:

        @contextmanager
        def stage(name):
            nonlocal sequence
            sequence += 1
            with tracer.start_as_current_span(
                name,
                attributes={
                    "request_id": request_id,
                    "sequence": sequence,
                },
            ):
                yield

        result = run_business(stage)

        decision = result["decision"]
        stop_stage = result["stop_stage"]
        trace_id = format(root_span.get_span_context().trace_id, "032x")

        root_span.set_attribute("decision", decision)
        root_span.set_attribute(
            "stop_stage",
            "" if stop_stage is None else stop_stage,
        )
        root_span.set_attribute("stage_count", sequence)

        logger.info(
            json.dumps(
                {
                    "request_id": request_id,
                    "trace_id": trace_id,
                    "decision": decision,
                    "stop_stage": stop_stage,
                }
            )
        )

        counter.labels(decision=decision).inc()

        return result
```

## 요구사항과의 대응

### 실제 업무는 한 번만 실행

`run_business(stage)` 호출은 root Span 안에 정확히 한 번만 있다. `stage()`는 업무 함수를 다시 호출하지 않고 업무가 전달한 실제 처리 구간만 감싼다.

### Root Span

`security.request` 이름으로 root Span을 만들고 시작 시점부터 알려진 `request_id`를 attributes에 넣는다. 업무가 끝난 뒤 정해지는 다음 값은 `set_attribute`로 기록한다.

- `decision`: 실제 업무 반환값
- `stop_stage`: 정상의 `None`은 Span attribute에서 빈 문자열
- `stage_count`: 실제 `stage()` 진입 횟수

### Child Span과 순번

`stage(name)`은 `@contextmanager`로 구현하며 진입할 때마다 `sequence`를 하나 증가시킨다. root Span이 current인 동안 child Span을 열기 때문에 업무가 호출한 각 단계가 root의 자식이 된다. 첫 단계는 1이고 이후 빈틈없이 증가한다.

`stage()`는 `yield` 값이 없으므로 UI가 요구한 “값을 반환하지 않는 context manager”를 만족한다.

### 실제 Trace ID

root Span context의 정수 trace ID를 다음 코드로 32자리 소문자 16진수로 바꾼다.

```python
format(root_span.get_span_context().trace_id, "032x")
```

임의 ID를 만들거나 request ID를 trace ID로 대신하지 않는다.

### JSON Log 한 건

요청마다 `logger.info`를 정확히 한 번 호출하며 `json.dumps()` 문자열에 다음 네 필드만 기록한다.

- `request_id`
- `trace_id`
- `decision`
- `stop_stage`

Log에서는 정상 `stop_stage`를 업무 결과의 `None` 그대로 JSON `null`로 기록한다. Span에서만 빈 문자열을 사용한다.

### Counter 한 번 증가

다음 한 호출로 실제 decision label의 counter만 증가시킨다.

```python
counter.labels(decision=decision).inc()
```

요청 ID는 metric label에 넣지 않는다.

### 원래 결과 보존

`result` dict를 복사하거나 수정하지 않고 동일한 객체를 그대로 반환한다. `downstream_count`와 `result` 필드를 telemetry용으로 제거하거나 바꾸지 않는다.

## 남은 누락 또는 모호성

채점 가능한 답을 막는 누락은 없다.

### Log와 Counter의 root Span 내부 실행

UI는 실제 Trace ID로 Log와 Trace를 연결하도록 요구한다. 위 구현은 root Span이 열린 동안 Log와 Counter를 기록하고 결과를 반환한다. `with`를 빠져나갈 때 root Span이 닫히므로 전체 계측 작업이 한 요청 구간에 포함된다.

### 업무 예외 시 telemetry

UI는 `run_business`가 명시된 dict를 반환하는 정상·거부 세 사례를 채점한다고 설명하며 업무 예외의 별도 Log/Counter 계약은 제시하지 않는다. 위 구현은 업무 예외를 잡아 성공 신호로 바꾸지 않고 그대로 전달하며 Span context는 정상적으로 닫힌다.

### JSON 직렬화 옵션

UI는 `json.dumps()` 사용만 요구하며 compact separator나 `ensure_ascii` 값을 지정하지 않는다. Log consumer가 JSON으로 parse하므로 기본 직렬화는 요구를 만족한다.

## 최종 결론

UI와 Starter만으로 P17 전체 구현을 완결할 수 있다. 위 답은 실제 업무를 한 번 실행하고, 업무가 진입한 단계만 순서 있는 child Span으로 남기며, 같은 실제 결과로 root attributes, JSON Log와 Counter를 각각 한 번 기록한다.
