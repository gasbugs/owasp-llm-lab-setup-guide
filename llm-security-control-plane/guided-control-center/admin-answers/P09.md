# P09 UI + Starter 독립 풀이 감사

## 판정

**가능**하다. UI와 미완성 Starter만으로 채점 가능한 완성 답을 명확히 도출할 수 있다.

Starter에서 필요한 변경은 네 가지다.

1. 공식 `KrRrnRecognizer`를 import한다.
2. 분석 대상 `ENTITIES`에 공식 entity 이름 `KR_RRN`을 추가한다.
3. recognizer의 `supported_language`를 현재 `LANGUAGE`인 `en`으로 지정해 Registry에 등록한다.
4. 최종 `released_text`에 원문 `text`가 아니라 `sanitized`를 사용한다.

## 완성 답

```python
"""Learner-owned H09 Presidio policy with PII redaction before release."""

from __future__ import annotations

from importlib.metadata import version

from presidio_analyzer import AnalyzerEngine
from presidio_analyzer.nlp_engine import NlpEngineProvider
from presidio_analyzer.predefined_recognizers import KrRrnRecognizer
from presidio_anonymizer import AnonymizerEngine
from presidio_anonymizer.entities import OperatorConfig


FRAMEWORK_VERSION = version("presidio-analyzer")
LANGUAGE = "en"
ENTITIES = ("EMAIL_ADDRESS", "KR_RRN")


def build_engines() -> tuple[AnalyzerEngine, AnonymizerEngine]:
    """Build the fixed English pipeline used by the learner policy."""
    nlp = NlpEngineProvider(
        nlp_configuration={
            "nlp_engine_name": "spacy",
            "models": [{"lang_code": LANGUAGE, "model_name": "en_core_web_sm"}],
        }
    ).create_engine()
    analyzer = AnalyzerEngine(nlp_engine=nlp, supported_languages=[LANGUAGE])
    analyzer.registry.add_recognizer(
        KrRrnRecognizer(supported_language=LANGUAGE)
    )
    return analyzer, AnonymizerEngine()


ANALYZER, ANONYMIZER = build_engines()


def apply_privacy_policy(*, stage: str, text: str) -> dict:
    """Analyze PII and choose the text released to the delivery boundary."""
    findings = ANALYZER.analyze(
        text=text,
        language=LANGUAGE,
        entities=list(ENTITIES),
        score_threshold=0.5,
    )
    operators = {
        finding.entity_type: OperatorConfig(
            "replace", {"new_value": f"<{finding.entity_type}>"}
        )
        for finding in findings
    }
    sanitized = (
        ANONYMIZER.anonymize(
            text=text,
            analyzer_results=findings,
            operators=operators,
        ).text
        if findings
        else text
    )
    detections = [
        {
            "entity_type": finding.entity_type,
            "start": finding.start,
            "end": finding.end,
            "score": round(float(finding.score), 4),
        }
        for finding in sorted(findings, key=lambda item: (item.start, item.end))
    ]
    return {
        "framework": "microsoft-presidio",
        "framework_version": FRAMEWORK_VERSION,
        "stage": stage,
        "entities": list(ENTITIES),
        "recognizer_classes": sorted(
            {type(item).__name__ for item in ANALYZER.registry.recognizers}
        ),
        "recognizers": sorted(
            {
                (type(item).__module__, type(item).__name__)
                for item in ANALYZER.registry.recognizers
            }
        ),
        "operator": "replace",
        "detections": detections,
        "sanitized_candidate": sanitized,
        "released_text": sanitized,
    }
```

## 조건 충족 확인

- 기존 영어 NLP pipeline과 `LANGUAGE = "en"`을 유지한다.
- `KrRrnRecognizer(supported_language=LANGUAGE)`로 등록하므로 영어 `analyze()` 요청에 참여한다.
- `ENTITIES`에 `EMAIL_ADDRESS`와 `KR_RRN`이 모두 있어 두 종류를 탐지한다.
- 기존 operator 생성 코드가 entity별 `<EMAIL_ADDRESS>`, `<KR_RRN>` 대체값을 만든다.
- 탐지 결과가 없으면 `sanitized`가 원문이므로 정상 문장은 그대로 전달된다.
- 탐지 결과가 있으면 Delivery 경계가 사용하는 `released_text`가 비식별화 문자열이다.
- 기존 `sanitized_candidate`, detection, recognizer 증거도 유지한다.

## 남은 누락과 경미한 해석 여지

채점 가능한 구현에 필요한 핵심 조건은 누락되지 않았다.

- UI는 합성 이메일·주민번호의 실제 입력값을 공개하지 않지만 공식 recognizer와 고정 threshold를 Starter가 제공하므로 구현을 결정하는 데 필요하지 않다.
- UI는 import 경로를 쓰지 않았지만 Starter의 Presidio 패키지 구조와 “공식 `KrRrnRecognizer`”라는 이름으로 표준 import를 결정할 수 있다.
- `ENTITIES` tuple의 순서는 명시되지 않았다. 기존 `EMAIL_ADDRESS` 뒤에 `KR_RRN`을 추가하는 것이 가장 작은 변경이며 반환 metadata도 안정적으로 유지한다.
- recognizer를 Analyzer 생성자에 전달하는 방식과 Registry에 `add_recognizer()`로 추가하는 방식 중 후자가 Starter 주석의 “registered” 요구와 현재 객체 구조에 직접 맞는다.
- 기존 operator comprehension은 같은 entity가 여러 번 탐지돼도 동일한 replacement config를 한 번 유지한다. 이는 모든 해당 범위를 같은 entity marker로 바꾸라는 요구와 일치한다.
