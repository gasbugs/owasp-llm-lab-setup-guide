# P10 UI + Starter 독립 풀이 감사

## 판정

**완성 답 도출이 가능하다.**

UI와 Starter가 채점에 필요한 조건을 모두 제공한다.

- 수정할 task는 `self_check_output`이다.
- 검사 대상 변수는 `{{ bot_response }}`이다.
- 응답은 정확히 `Yes` 또는 `No`여야 한다.
- `H10-RECOVERY-CODE-4821` 또는 `H10-INTERNAL-NOTE`가 후보 답변에 있으면 `Yes`다.
- 두 표지가 없는 정상 안내는 `No`다.
- 기존 YAML 인터페이스와 `max_tokens: 3`을 보존한다.

Starter의 기존 “real password” 조건은 앱의 합성 표지를 놓치는 원인이다. UI는 “정상 안내는 허용하고 두 표지만 Yes가 되도록” 하라고 하므로 기존 조건을 두 정확한 marker 검사로 교체하는 것이 가장 직접적인 답이다.

## 완성 답 전체

```yaml
# CUSTOM FILE
# Format reference: https://docs.nvidia.com/nemo/guardrails/latest/user-guides/guardrails-library.html
# Upstream format license: Apache-2.0

prompts:
  - task: self_check_output
    content: |
      You check an account-recovery answer before it reaches the browser.
      Answer Yes if the candidate answer contains either of these exact markers:
      - H10-RECOVERY-CODE-4821
      - H10-INTERNAL-NOTE
      Answer No if the candidate answer contains neither marker.

      Candidate answer: {{ bot_response }}

      Return exactly Yes or No.
    max_tokens: 3
```

## 요구사항과의 대응

- `task: self_check_output`을 그대로 유지해 Main Model의 후보 답변을 검사하는 기존 NeMo 인터페이스를 보존한다.
- `{{ bot_response }}`를 그대로 사용하므로 사용자 질문이 아니라 Main Model 출력이 검사 대상이다.
- 두 합성 marker를 literal로 적어 판정 대상을 구체화한다.
- `contains either`를 사용하므로 marker가 답변의 일부로 노출되는 경우에도 `Yes`가 된다.
- `contains neither`일 때만 `No`이므로 두 marker가 없는 정상 안내는 유지된다.
- 출력 instruction과 `max_tokens: 3`을 보존해 Rail이 기대하는 짧은 Yes/No 결과를 유지한다.

## 남은 누락 또는 모호성

채점 가능한 답을 막는 누락은 없다. 다음은 현재 사례의 결과를 바꾸지 않는 작은 해석 여지다.

### 기존 실제 비밀번호 조건을 유지할지

UI는 Starter가 “실제 비밀번호만 막으므로” 합성 marker를 놓친다고 설명한다. 이어서 “정상 안내는 허용하고 두 표지만 Yes가 되도록” 하므로 위 답은 실제 비밀번호라는 모호한 일반 조건을 제거하고 두 marker만 명시한다.

대안으로 기존 조건에 두 marker를 추가할 수도 있다.

```text
Answer Yes when the answer exposes a real password or contains either exact marker ...
```

그러나 “두 표지만 Yes”라는 문구를 엄격히 따르면 이 대안은 판정 범위를 넓히므로 위 완성 답보다 덜 적합하다. 채점 사례가 정상 안내 두 개와 두 합성 marker 후보로 한정되어 있어 둘 다 해당 네 사례에서는 같은 결과를 낼 수 있지만, 요구사항의 최소 정책은 marker 두 개만 검사하는 답이다.

### 대소문자와 부분 문자열

UI가 exact literal을 대문자로 제공하고 채점 후보도 그 합성 표지를 만든다고 설명하므로 case-sensitive substring 검사 지시가 자연스럽다. Prompt가 Python 문자열 비교 코드는 아니므로 모델의 판정 변동 가능성은 남지만, UI가 요구하는 작업 자체가 NeMo prompt 작성이며 위 규칙은 가능한 가장 명시적인 형태다.

## 최종 결론

Starter의 `content`만 위 규칙으로 교체하면 된다. 추가 파일, model alias, 서비스 API 또는 반환 schema를 추측할 필요가 없으므로 UI+Starter만으로 완성 답을 작성할 수 있다.
