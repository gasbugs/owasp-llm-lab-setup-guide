# P07 UI+Starter 최종 재감사

## 판정

**완성 답을 정확히 작성할 수 있다.**

UI는 추가할 모델의 역할명, engine을 재사용할 골격, 정확한 alias, 두 parameter 값과 공식 input flow 문자열을 모두 제공한다. Starter는 기존 Main 모델과 `rails.input.flows`의 위치를 보여 준다. 따라서 임의의 schema나 이름을 만들 필요가 없다.

## 완성된 `config.yml`

```yaml
# CUSTOM FILE
# Format reference: https://docs.nvidia.com/nemo/guardrails/latest/configure-rails/configuration-guide.html
# Upstream format license: Apache-2.0

models:
  - type: main
    engine: openai
    model: us.amazon.nova-lite-v1:0#h07-main
    parameters:
      temperature: 0.0
      max_tokens: 120

  - type: content_safety
    engine: openai
    model: us.amazon.nova-lite-v1:0#h07-content-safety
    parameters:
      temperature: 0.0
      max_tokens: 120

rails:
  input:
    flows:
      - content safety check input $model=content_safety
```

## 답의 근거

- 기존 `main` 모델과 alias `us.amazon.nova-lite-v1:0#h07-main`을 그대로 유지한다.
- 같은 `openai` engine 골격으로 `type: content_safety` 모델을 하나 추가한다.
- 입력 검사 alias를 UI가 지정한 `us.amazon.nova-lite-v1:0#h07-content-safety`로 설정한다.
- 두 모델 모두 `temperature: 0.0`, `max_tokens: 120`을 사용한다.
- 빈 input flow 목록을 공식 flow `content safety check input $model=content_safety` 한 개로 교체한다.
- 역할명과 `$model` 값이 모두 `content_safety`이므로 Rail이 입력 검사 전용 모델을 사용한다.
- 정상 요청은 input Rail을 통과한 뒤 기존 Main으로 가고, 위험 요청은 input Rail에서 멈추도록 하는 구성이다.

## 남은 누락

구성 파일을 완성하는 데 필요한 조건은 남아 있지 않다.

실제 정상 요청에서 Content Safety 1회와 Main 1회, 위험 요청에서 Content Safety 1회와 Main 0회가 되는지는 서비스를 빌드·재생성한 뒤 NeMo event와 Gateway 원장으로 검증해야 한다. 이는 정답 구성의 누락이 아니라 UI가 별도로 요구한 실행 검증 단계다.
