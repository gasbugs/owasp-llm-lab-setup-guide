    P01 · Gateway 만들기

    정상 상담은 통과! 과도한 호출은 정지!

    당신은 고객 상담 서비스의 Gateway 개발자입니다. Starter의 입력 검사·분기·예외 처리 흐름을 따라 예산 예약·모델 호출·정산의 핵심 줄을 완성하세요.

    1. 01 · 입력 검사필수 필드, 메시지 길이, 숫자 타입을 검사해 잘못된 요청을 모델 호출 전에 거부하세요.
    2. 02 · 답변 길이 제한요청한 출력 상한이 128 이하면 그대로 전달하고, 더 크면 128로 낮추세요.
    3. 03 · 사용 예산 관리호출 전에 사용할 양을 예약하고, 성공하면 실제 사용량으로 정산하세요. 실패하면 예약을 취소하세요.

    Token은 모델이 문장을 처리하는 단위입니다. 출력 상한은 답변에 쓸 수 있는 최대 Token 수이고, 사용 예산은 여러 요청에서 쓸 수 있는 총량입니다.

    클리어 조건 정상 요청 7개 · 잘못된 입력 14개 · 예산 검사 2개, 총 23개 테스트를 모두 통과하고 최종 보안 결과가 PASS이면 미션 완료입니다.

    제공된 시작 코드(Starter)의 HTTP 501은 함수가 아직 구현되지 않았다는 뜻입니다. 아래 조건에 맞게 구현하고 적용한 뒤 미션 채점을 누르세요. 실패하면 RAW 응답의 case_id로 어떤 테스트에서 멈췄는지 확인하세요.

    직접 작성할 함수

    미션 해결 조건 — 이 조건을 만족하는 함수를 작성하세요

    ~/owasp-llm-practice/P03-01_learner.py의 handle_request(body, client)에서 TODO 2~4의 핵심 호출을 작성합니다. 입력 검사와 if·try/except 구조는 Starter에 있습니다. body는 사용자가 보낸 JSON이고, client.converse()는 AWS Python 라이브러리 Boto3와 같은 방식으로 모델을 호출하는 제공 함수입니다. 인증 Token과 실행 기록은 수정하지 않습니다.

    • message와 max_output_tokens만 받습니다. 누락되거나 다른 필드가 있으면 거부합니다.
    • 메시지는 1~4,000자 문자열이어야 하며 공백만 있으면 거부합니다. 출력 상한은 1~512 정수만 받습니다. 문자열·실수·참/거짓 값은 허용하지 않습니다.
    • 잘못된 요청은 ValueError로 거부합니다. 서버가 이를 HTTP 422로 바꿉니다. 이때 모델을 호출하면 안 됩니다.
    • 정상 요청은 us.amazon.nova-lite-v1:0에 사용자 메시지로 한 번 전달합니다. 답변의 무작위성을 조절하는 temperature는 0.0으로 설정하고 입력 문장은 그대로 유지합니다.
    • 요청한 출력 상한이 128 이하면 그대로 쓰고, 더 크면 128로 제한합니다. 예를 들어 37은 37, 301은 128로 전달해야 합니다.
    • 호출 전에 client.reserve_budget(실제 출력 상한)으로 출력 Token 예산을 예약합니다. 성공하면 client.settle_budget(예약 ID, 응답의 usage.outputTokens)로 실제 사용량을 정산하고, 호출 실패 시 client.cancel_budget(예약 ID)로 취소한 뒤 오류를 그대로 전달합니다. 예산 부족 오류도 그대로 전달하면 서버가 HTTP 429로 처리합니다.
    • 실제 Converse 응답을 그대로 반환합니다. 답변이나 검증 결과를 직접 만들어 반환하지 않습니다.

    bundle의 logs는 결정 기록, spans는 처리 단계, closures는 처리가 끝났다는 기록, downstream_calls는 실제 저장소 호출 목록입니다. 모두 request_id·trace_id로 연결합니다.
    
              
    서버 수집기는 원시 Log의 client_ip·user_id·policy_rule과 security.request root Span을 먼저 대조한 뒤, 학습자 함수에는 정규화한 bundle만 전달합니다. 따라서 spans에는 root가 없고 분석할 단계 Span만 있습니다. 각 행은 사전이며, 대상 요청과 무관한 행은 내용이 불완전해도 제외합니다. 대상 trace_id는 비어 있지 않은 문자열이어야 하고, 같은 단계 이름이 반복되는지는 별도 오류가 아닙니다. 순서의 유일성과 연속성은 sequence로 판단하며, 거부 요청의 stop_stage는 sequence상 마지막 stage와 정확히 같아야 합니다.
